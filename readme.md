# 🧠 Kingslayer / Digital Double (Цифровой Двойник)

Пет-проект по дообучению (fine-tuning) языковой модели Google Gemma так, чтобы она отвечала в моём личном стиле общения. Обучение — QLoRA (4-битное квантование + LoRA-адаптеры) на собственной переписке из Telegram.

## 📂 Структура проекта

| Файл / папка | Назначение |
|---|---|
| `msg.py` | Парсит экспорт переписки из Telegram (`result.json`) в датасет пар `instruction` → `output` (потоково, через `ijson`, чтобы не грузить весь экспорт в память). |
| `dataset.jsonl` | Датасет для обучения в формате JSON Lines. **В репозиторий не включён** — содержит реальную личную переписку (см. раздел «Данные и приватность»). |
| `check.py` | Быстрая проверка окружения — что `torch`/`transformers` импортируются без конфликтов. |
| `train.py` / `train_gemma2.py` | Скрипт обучения на **Gemma 2 2B**: 4-битное квантование (NF4) + LoRA. Оба файла идентичны, `train_gemma2.py` оставлен как явная версия под конкретную модель. |
| `train_gemma3.py` | Вариант скрипта обучения под **Gemma 3 4B**, с обходом проблем совместимости (см. ниже). |
| `chat.py` | Загружает базовую модель + обученные LoRA-адаптеры и запускает интерактивный чат с «двойником» в консоли. |
| `my_digital_double_model/` | Результат обучения: LoRA-адаптеры (`adapter_model.safetensors`) и токенайзер. |

## 🛠 Как это устроено

### 1. Подготовка данных

`msg.py` разбирает JSON-экспорт переписки из Telegram, склеивает подряд идущие сообщения одного автора в блоки и формирует пары «реплика собеседника → мой ответ». Каждая пара оборачивается в служебные токены формата Gemma:

```
<start_of_turn>user
{вопрос}<end_of_turn>
<start_of_turn>model
{мой ответ}<end_of_turn>
```

### 2. Обучение (QLoRA)

Модель дообучается не целиком, а через LoRA-адаптеры (низкоранговые матрицы поверх `q_proj`, `k_proj`, `v_proj`, `o_proj`, `gate_proj`, `up_proj`, `down_proj`), при этом сама базовая модель загружается в 4-битном квантовании (NF4). Это позволяет обучать модель на 11 ГБ видеопамяти (RTX 2080 Ti):

- **NF4-квантование** — сжимает модель до ~5–6 ГБ вместо ~16 ГБ в fp16.
- **Gradient accumulation** — обновление весов реже, чем прямой проход, что экономит память без потери качества обучения.
- Обучаются только LoRA-веса — базовая модель остаётся неизменной, что и позволяет распространять только маленький адаптер (~80 МБ), а не всю модель.

### 3. Совместимость с Gemma 3

Gemma 3 требует PyTorch ≥ 2.6 для нового механизма маскирования внимания; на связке Windows + RTX 2080 Ti была доступна только 2.5.1. Обходной путь в `train_gemma3.py`:

- `attn_implementation="eager"` — отключает несовместимые оптимизации внимания.
- Принудительная передача `token_type_ids` — без них Gemma 3 падает во время обучения на этой версии `transformers`.

## 🚀 Как запустить

### Требования

- Python 3.10+, CUDA-видеокарта (проверено на RTX 2080 Ti, 11 ГБ VRAM).
- `pip install torch transformers peft bitsandbytes datasets accelerate ijson`.
- Доступ к весам `google/gemma-2-2b-it` (или `gemma-3-4b`) на Hugging Face.

### Шаг 1 — собрать свой датасет

Экспортируй переписку из Telegram Desktop (Settings → Advanced → Export Telegram data → JSON) и укажи в `msg.py` своё имя и имя собеседника, затем запусти:

```bash
python msg.py
```

На выходе — `dataset.jsonl`.

### Шаг 2 — обучение

```bash
python train.py          # Gemma 2 2B
python train_gemma3.py   # Gemma 3 4B (экспериментально)
```

Ориентиры во время обучения:
- **Loss** должен падать (например, с ~8.0 до ~0.2) — если так, всё идёт штатно.
- **VRAM** будет занята почти полностью (10.5–11 ГБ на 2080 Ti).

Результат сохраняется в `my_digital_double_model/`.

### Шаг 3 — общение с двойником

```bash
python chat.py
```

Скрипт подгружает базовую модель Google и накатывает поверх неё обученные LoRA-адаптеры.

## 🔒 Данные и приватность

`dataset.jsonl` строится из реальной личной переписки и **намеренно не включён в этот репозиторий** — он в `.gitignore`. Чтобы воспроизвести проект, сгенерируй собственный датасет из своего экспорта Telegram через `msg.py` (см. «Шаг 1» выше).

## ⚠️ Заметки

- Не редактируй `torch.__version__` вручную — ломает импорт `bitsandbytes` с `TypeError`.
- При обучении видеокарта прогревается до 75°C+ — важна продувка корпуса.
- Если что-то не импортируется — проверь `pip install accelerate`.
